# EveryAI 清洗转型期间的路由说明

> 生产已在既有`everyinfra_chat`兼容工具之外提供来源绑定清洗。每次执行仍须实时发现两个清洗
> 工具；工具存在不证明特定账户已达标、激活或完成端到端实测。

## 路由规则

先区分普通文本处理与 EveryData 结果后处理。

| 目标 | 当前路由 | 清洗正式上线后 |
| --- | --- | --- |
| 分类、抽取、翻译或摘要用户直接提供的文本 | 在实时 schema 存在且用户授权时，走 EveryAI 的 `everyinfra_chat`。 | 按有明确日期的兼容通知处理；清洗不会自动替代所有普通文本任务。 |
| 处理已验证的 EveryData 结果 | 发现实时MCP或REST清洗契约，再核权益、来源所有权/版本及配方；不能改送通用聊天。 | 继续遵循同一来源绑定契约及届时的迁移通知。 |
| 可确定性完成的规范化 | 优先普通代码。 | 上线后仍不强制经过模型。 |
| 获取或核验当前信息 | 走 EverySearch 或 Research。 | 清洗仍是处理，不是检索或证据。 |

首期计划是有条件权益，不是无限免费：可核净结算充值本金达到人民币 500 元、显式领取、30 天、
每日最多 1,000 个成功单元、总计最多 30,000 个成功单元、同账户每分钟最多 5 次执行提交、
最多 5 个并发单元。这些是已确认的实现契约，不代表功能或生产容量已经上线。

## 已上线的 15 操作路由

生产有两个工具；执行前仍须重新读取MCP `tools/list`和实时`inputSchema`。

| 工具 | 操作 |
| --- | --- |
| `everyinfra_data_cleanup_read` | `get_entitlement`、`get_source`、`get_source_fields`、`list_recipes`、`preview`、`list_jobs`、`find_job`、`get_job`、`list_units`、`get_result`、`export` |
| `everyinfra_data_cleanup_action` | `activate`、`submit`、`cancel`、`delete_result` |

路由顺序：发现工具→查询权益→发现来源版本/字段/固定配方→预览→必要时显式领取→
显式提交。读取不授权写动作。刷新或提交结果未知时，保留原幂等键，用`list_jobs`或`find_job`
找回原任务，再查任务、单元和结果。404不能证明原提交未受理，不能因此自动换键或换通道重提。

## 发现与失败处理

1. 执行时读取生产 MCP `tools/list` 或公开 OpenAPI。
2. 当前宿主没有发现清洗能力时，返回不可用状态，不生成猜测请求。
3. 发现清洗后，先查看实时权益、来源与配方 schema，再做预览或提交。
4. 领取和执行是两个独立写动作；读取或预览不授权它们。
5. 执行结果未知时保留原幂等操作，不切换传输或退回通用聊天重复执行。

旧通用聊天在公布明确退役通知前仍是兼容接口。计划中的 30 天客户迁移期与账户 30 天清洗权益
是两个不同周期，不得猜测开始或截止日期。

## 三层交付边界

- **Skill** 是路由和工作方法；更新只改变 Agent 指引。
- **MCP** 是运行时工具和 schema；以线上发现与执行证明可用性。
- **Plugin** 是可安装分发包，可包含 Skill、MCP 元数据或两者；源码公开、安装和市场上架均不等于服务已启用。
